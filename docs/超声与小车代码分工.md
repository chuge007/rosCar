> 目的：改动前先判定"这是超声的事还是小车的事"，从而只碰该碰的文件、只编该编的目标、只看该看的日志。

## 0. 三类功能 + 一层共享协议

项目不是"两类"，而是**三类功能 + 一层共享协议**：

| 组 | 名称 | 代码位置 | 运行位置 |
|----|------|----------|----------|
| U | 超声（采集 / 成像 / 参数 / 预设） | `src/` 根目录的 device/scan/parameter 系列 + `src/services/` + `src/backend/ultrasound_*` | Workbench（本地模式直连 SDK）+ RobotHost（远程模式服务端） |
| R | 小车（底盘 / 电机 / IMU / 相机 / 夹爪） | `src/robot/` + `src/robot_*.cpp`、`robotcontrolpanel.*`、`src/backend/robot_*.cpp` | 同上 |
| L | 激光 / 视觉焊缝（轮廓、纠偏、点云、相机进程） | `src/laser_*`、`src/camera_*`、`src/*weld_locator.h`、`vendor/mv3dlp_laser_profile/` | 车体侧执行，Workbench 只做显示 |
| S | 协议与传输共享层 | `src/common/` | 两端 |

三个可执行目标：

| 目标 | 入口 | 主要归属 |
|------|------|----------|
| `PA1664Workbench` | `src/main.cpp` | U + R + L 的 GUI |
| `PA1664RobotHost` | `src/backend/main.cpp` | R + L 执行体，兼 U 的远程服务端 |
| `PA1664CameraServer` | `src/camera_server_main.cpp` | L 相机独立进程 |

## 1. 超声（U）

### U1 采集与解码（硬件 → 结构化帧）
- `src/devicecontroller.cpp/.h` — 厂商 SDK / USB 采集入口，`packetCallback` 收包进显示队列与 C 扫队列
- `src/packetdecoder.cpp/.h` — 裸包 → `DecodedFrame`（A/E 扫、测量值、编码器/帧号）
- `src/framedecoderworker.cpp/.h` — 显示解码线程 + 编码器触发 C 扫批，产出 `frameDecoded` / `groupScanBatchDecoded`
- `src/pulseloadguard.cpp/.h` — 采集节流 / 负载保护
- `src/rawpacket.h` — 裸包缓冲类型
- `src/usbbootstrap.cpp/.h` — 超声 USB 固件 BootLoader → Streamer 引导（**被三个入口共用**）

### U2 显示（Workbench）
- `src/scanwidgets.cpp/.h` — `AScanWidget / BScanWidget / CScanWidget / EScanWidget` + `CScanRenderer`
- `src/scanwaveformcache.cpp/.h` — B/C 扫波形缓存线程
- `src/mainwindow.cpp/.h` — 装配者（`acceptDecodedFrame` / `acceptGroupScanBatch` / `ensureBScan` / `ensureCScan`）

本地数据流：`DeviceController` → `FrameDecoderWorker` → `PacketDecoder` → `MainWindow::acceptDecodedFrame` → `ScanWaveformCache` + 各 Scan 控件。

### U3 参数与预设
- `src/parameterpanel.cpp/.h` — 超声参数 UI（声束 / 闸门 / 滤波 / 增益）
- `src/parameterpresetstore.cpp/.h` — 预设文件存储（超声专属基础设施，虽在 `src/` 根目录）
- `src/services/ultrasound_parameter_service.cpp/.h` — 门面：本地直连 SDK，远程走 RPC
- `src/probeadjustmentpanel.cpp/.h` — 「探头调节」超声 UI，**通过 `crawling::ClampMotorController` 驱动电机**（交界点）

### U4 远程超声（RobotHost 侧）
- `src/backend/ultrasound_host_service.cpp/.h` — Host 独占 SDK / DeviceController 调用，按 operation 分派
- `src/backend/ultrasound_parameter_rpc.cpp/.h` — 对厂商 `Client` 的反射读写
- `src/services/remote_ultrasound_source.cpp/.h` — 操作端适配器：media 收实时帧、bulk 收扫描批、control 发命令

参数 RPC 路径：`ultrasound_parameter_service` → `RemoteWorkbenchSession::request` → `ControlClient`(TCP 43100) → `host_application::onRequest` → `ultrasound_host_service::handleRequest` → `UltrasoundParameterRpc::read/write`。
能力串在 `src/common/protocol/protocol_types.h`（`ultrasound.control.v1 / parameters.v1 / media.v1 / bulk.v1`，超声媒体流基址 `kMediaStreamUltrasoundLiveBase = 0x0100`）。

### U5 录制 / 回放 / 本机 IPC
- `src/framerecorder.cpp/.h`、`src/frameplayer.cpp/.h`
- `src/remotecontrolserver.cpp/.h` — 同机 QLocalServer 白名单（只持有 `DeviceController` + `ParameterPanel`）

## 2. 小车（R）

### R1 UI
- `src/robotcontrolpanel.cpp/.h` — 「小车控制」页：模式、点动、状态、配置、自动纠偏、外设连接
- `src/robot_profile_view.cpp/.h` — 激光轮廓 X/Z 视图与焊道判定显示（数据属 L1，界面挂在小车页）

### R2 控制环
- `src/robot/synchronized_drive_controller.cpp/.h` — 双轮同步控制环（`controlTick` / `setInputCommand` / `enterFault`）
- `src/robot/wheel_synchronizer.cpp/.h`、`src/robot/differential_mixer.cpp/.h` — 同步校正 / 差速解算
- `src/robot/drive_settings.cpp/.h`、`src/robot/drive_types.h` — 配置与遥测结构

### R3 执行层（CAN / 串口）
- `src/robot/wheel_motor_controller.cpp/.h` — 轮电机适配，按 `communicationMode` 走 CAN 或 RS485
- CAN：`src/robot/candle_can_adapter.cpp`、`src/robot/pcan_can_adapter.cpp`、`src/robot/zdt_can_protocol.cpp`
- 串口：`src/robot/servo_protocol.cpp`、`mwd_rs485_protocol.cpp`、`mwd_modbus_protocol.cpp`、`rim302_protocol.cpp`（IMU）
- 探测：`src/robot_hardware_discovery_qt6.cpp` + `src/robot/hardware_discovery.h`
- 夹爪 / 辅助电机：`src/robot/clamp_motor_controller.cpp`、`src/robot/clamp_motor_widgets.cpp` → **归小车端**

### R4 车体外设
- `src/robot_sensor_controller.cpp/.h` — RIM302 IMU
- `src/robot_usb_camera_controller.cpp/.h` — 相机（经 `camera_server_client` 连独立进程）
- `src/network_stream_reader.cpp/.h`、`src/camera_frame_processor.cpp/.h`

### R5 Host 服务端 RPC
- `src/backend/robot_host_service.cpp/.h` — `system.snapshot`、`robot.connect/disconnect/enable/motion.stop/emergencyStop/reset/clearAlarm/settings.*`
- `src/backend/robot_peripheral_host_service.cpp/.h` — `robot.imu.*`、`robot.laser.*`、`robot.camera.*`、`robot.clamp.*`、`robot.autoCorrection.*`
- 运动实时通道：`src/common/protocol/realtime_codec.*` + UDP 43101，200 ms 租约

本地数据流：`RobotControlPanel` →（`Qt::QueuedConnection`）→ `SynchronizedDriveController`（独立线程）→ `WheelMotorController` → CAN(`candle/pcan`) 或 串口(`servo/mwd_rs485/mwd_modbus`)。
远程数据流：`RobotControlPanel` → `RemoteWorkbenchSession::setMotion/request` → `robot.control.v1` → `RobotHostService` → 同一条控制环。

## 4. 共享层（S）与风险

| 文件 | 职责 | 使用者 |
|------|------|--------|
| `src/common/protocol/protocol_types.h` | 端口 / 帧长 / 能力串 / 流 ID | 两端全部 |
| `src/common/protocol/control_codec.*` | 可靠控制帧 | U + R 的 RPC |
| `src/common/protocol/realtime_codec.*` | 实时 UDP（设定点 / 遥测 / 急停） | **仅 R**，属运动安全路径 |
| `src/common/protocol/media_codec.*` | 媒体分片 / HMAC / 重组 | U + L |
| `src/common/protocol/bulk_codec.*` | 大批量流 | U + L |
| `src/common/transport/*` | control / realtime / media / bulk 通道 | 两端 |
| `src/common/services/remote_workbench_session.*` | 四通道聚合 + 能力协商 | U + R 全部远程调用 |
| `src/common/services/workbench_data_codec.*` | media / bulk 载荷编解码 | **双用途**：超声帧 + 焊缝观测 |
| `src/common/services/robot_json_codec.*` | 车体 / 激光 JSON | 仅 R / L |
| `src/common/services/parameter_key.h` | 参数键命名 | U |

改共享层的硬性要求：
1. 任何协议常量（分片大小、帧长上限、超时）改动，**两端必须同版本升级**，否则老操作端会直接拒包。
2. `realtime_codec` 涉及下发周期、租约、急停，改它等于改运动安全，必须单独评审。
3. `remote_workbench_session` 的能力门控一变，超声与小车两套 RPC 同时受影响。
4. `workbench_data_codec` 是唯一真正双用途的编解码文件，改编码必须同时验证超声成像与焊缝观测。

## 5. 交界点（改动前必须显式确认）

1. `src/mainwindow.cpp` — 唯一同时装配「超声检测」页与「小车控制」页的地方（本地 / 远程两套构造分支），允许同时引用两侧。
2. `src/probeadjustmentpanel.cpp` — 超声 UI 却驱动小车电机（`ClampMotorController`，远程走 `robot.clamp.*`），改超声可能触碰电机安全。
3. `src/usbbootstrap.cpp` — 三个入口都调用，属超声基础设施而非通用层。
4. `src/parameterpresetstore.cpp` — 超声专属，不要当共享层。
5. `src/robot/hardware_discovery.h` + `src/robot_hardware_discovery_qt6.cpp` — 探测器可能枚举到超声 USB 设备，改枚举逻辑要考虑两侧。

## 6. 日志归属（以代码为准）

落盘位置是**可执行文件所在目录**（小车端即 `C:\Users\a\Desktop\robot_host\app\logs\`）：

| 文件 | 产生位置 | 内容 |
|------|----------|------|
| `logs/robot_host.log` | `src/backend/main.cpp` 的消息处理器 | Host 全部 qDebug/qInfo：超声服务 + 车体 + 激光，混在一处 |
| `logs/robot_console.log` | `src/robot_app_logger.cpp` + `src/main.cpp` 的 `QT.MESSAGE` 钩子 | Workbench 主日志：小车控制 + 超声 UI/SDK 的 qDebug |
| `logs/camera_connection.log` | `robot_app_logger.cpp`（`CAMERA.*` 类别） | 相机连接 |
| `logs/profile_weld_detection.log` | `robot_app_logger.cpp`（`AppLogger::writeProfileDetection`） | 焊缝轮廓诊断 |
| `logs/comm/<category>.log` | `robot_app_logger.cpp`（`COMM.*` → 分文件） | 通信层，如 `comm/control.log` |
| `logs/log_YYYYMMDD_HHMMSS.txt` | 厂商超声 SDK 自写 | SDK 原始日志 |

- 写 `AppLogger` 的集中在**小车 / 通信侧**（`clamp_motor_controller`、`robot_sensor_controller`、`robot_usb_camera_controller`、`network_stream_reader`、`wheel_motor_controller`、`robotcontrolpanel`、`synchronized_drive_controller`、`realtime_channel`、`control_client`、`robot_profile_view`、`probeadjustmentpanel` 的 `PROBE.SPACING`）。
- 超声模块（`devicecontroller` / `parameterpanel` / `scanwidgets` / `framedecoderworker`）**不写 AppLogger**，只能随 Qt 消息落 `robot_console.log` 或 `robot_host.log`。
- 因此：**不存在"超声专属日志文件"**，排查时用类别前缀 + 进程区分。
- 部署目录另有 `Mv3dLpLog/`（激光 SDK）、`RobotControl/logs/`（部署脚本建的历史路径），代码当前不主动写入这两处，排查激光问题时才看。
- Workbench 启动时会 truncate `robot_console.log` 与 `camera_connection.log`，`robot_host.log` 为 append。

## 7. 改代码的标准流程

### 第一步：归类
按 §1–§3 判断改动属于 U / R / L / S。判定不了就说明理由并先问，不要凭文件名猜。

### 第二步：圈定文件与影响面
- 只改本类文件；需要动另一类的文件（含 `mainwindow`、`probeadjustmentpanel`、`src/common/*`）时，先在回复里说明"为什么必须越界、会影响哪一侧"。
- 改任何函数 / 类前先做一次影响面分析（GitNexus `impact`，或至少 `search_content` 找出全部调用点）。

### 第三步：只编对应目标
```bat
build_workbench.bat      :: PA1664Workbench（超声 / 小车 / 激光 GUI）
build_host.bat           :: PA1664RobotHost（车体执行 + 超声远程服务端）
build_all.bat            :: PA1664CameraServer + PA1664Workbench（脚本内不含 Host）
```
改 U 的采集/解码/UI → Workbench；改 U 的远程服务 → Host；改 R 的控制环/协议 → 两个目标都要编（Workbench 本地模式与 Host 共用同一份 `src/robot/` 代码）。需要三个目标全编时按 `build_workbench.bat` → `build_host.bat` → `build_all.bat` 依次执行，`build_all.bat` 单独跑不会产出 `PA1664RobotHost.exe`。
改完必须用 clangd + `compile_commands.json` 检查（项目规则要求），确认没有编译级错误。

### 第四步：验证
1. 本地跑：`bin\PA1664Workbench.exe` / `bin\PA1664RobotHost.exe`，看 `bin\logs\` 下对应日志。
2. 远程跑：`ssh a@192.168.1.20`，部署目录 `C:\Users\a\Desktop\robot_host`，看 `app\logs\`。
3. 超声侧必看：A/E 扫是否有数据、C 扫批是否到达、参数读写是否成功、有无 `ultrasound.*` 请求失败日志。
4. 小车侧必看：`DRIVE.CONTROL` / `IMU.COMM` / `COMM.*` 事件是否正常，急停与租约是否有效。

### 第五步：部署（仅小车端 Host）
停进程 → 备份旧 EXE → `scp` 新 EXE 到 `C:/Users/a/Desktop/robot_host/app/` → 校验 → 启动。细则见 [远程调试与部署指南](远程调试与部署指南.md)。
