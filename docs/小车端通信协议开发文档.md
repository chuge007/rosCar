# PA1664 小车端通信协议开发文档

> **本文档只讲线格式与会话层。**
> 按功能查阅（"我要做某件事，往哪发、发什么字节"）请看同目录的
> [`小车端功能接口手册.md`](./小车端功能接口手册.md)，那里一个功能一条，含完整报文与二进制示例。
> 下文附录 A 是旧版压缩表，仅作速查，**以功能手册为准**。

适用对象：需要通过 TCP/UDP 直接控制 PA1664 小车与超声设备、并接收回传数据的第三方软件。

代码基线：`src/common/protocol/`（线格式）、`src/common/transport/`（通道）、`src/backend/*_host_service.cpp`（指令实现）。

协议版本：`kProtocolVersion = 1`。整数一律小端；JSON 一律 compact。

---

## 1. 架构定位

| 职责 | 小车端（PA1664RobotHost） | 上位机（Workbench 或第三方软件） |
|---|---|---|
| 硬件访问 | 超声 SDK、轮电机 CAN/RS485、夹爪电机、IMU、激光 SDK、USB/网络相机 | 无 |
| 运动闭环 | 速度闭环、差速、轮同步、加减速限幅、租约超时停车 | 每 50 ms 下发一次设定值 |
| 安全校验 | PRF 限幅、参数写后回读校验、配置版本/范围校验、操作台独占 | 不做最终裁决 |
| 数据加工 | 压缩、分片、编码、节流 | 分片重组、解压、解码、渲染 |
| 持久化 | 超声预设、底盘 INI、编码器标定 | 只缓存显示值 |

结论：**控制与安全计算在车上；上位机负责交互、解码与显示。** 上位机不参与闭环，断链后车会在 200 ms 租约到期时自动停。

## 2. 连接参数

| 用途 | 传输 | 默认端口 | 监听地址 | 方向 |
|---|---|---|---|---|
| 指令下发 / 参数设置 / 事件回传 | TCP | 43100 | 0.0.0.0 | 双向 |
| 运动设定值 / 急停 / 遥测 | UDP | 43101 | 0.0.0.0 | 双向 |
| 超声图像 / 点云 / 相机 / IMU | UDP | 43102 | 0.0.0.0 | 以 Host→上位机 为主 |
| 整包扫查批次（可靠） | TCP | 43103 | 0.0.0.0 | Host→上位机 为主 |

- IP：小车主机地址，现场默认 `192.168.1.20`。
- 端口可在启动时改（四个端口必须互不相同）：

```
PA1664RobotHost.exe --listen 0.0.0.0 --control-port 43100 ^
                    --realtime-port 43101 --media-port 43102 --bulk-port 43103
```

- 实际生效值以 `app\logs\robot_host.log` 首行为准：
  `PA1664RobotHost 已启动：control/tcp=0.0.0.0:43100 realtime/udp=... media/udp=... bulk/tcp=...`
- 握手回包里的 `realtimePort/mediaPort/bulkPort` 是权威值，客户端不要写死。

**不要只实现 43100。** 只用 TCP 可以设参数、读状态，但无法让车运动——速度指令只走 43101 的 UDP `MotionSetpoint`。

## 3. 会话建立与保活

### 3.1 时序

1. TCP 连接 `小车IP:43100`。
2. 客户端发 `Hello`：`type=1`、`sessionId=0`、`sequence=1`、`requestId=<自增>`。
3. Host 校验 `protocolVersion`，生成 `sessionId`（非 0）与 32 字节随机 `sessionKey`，回 `HelloAck`：`type=2`、`flags=ResponseToRequest`、`requestId` 与 Hello 相同。
4. Host 尝试独占：底盘 → 外设 → 超声。成功则下发事件 `host.ready`；失败则下发 `host.busy` 并在 250 ms 后断开。
5. 客户端后续所有控制帧必须携带 ack 里的 `sessionId`，`sequence` 从 2 起严格递增。
6. 每 `heartbeatIntervalMs`（默认 250 ms）发 `Ping`（`type=6`），Host 回 `Pong`（`type=7`，同 `requestId`）。

### 3.2 Hello

| 字段 | 类型 | 说明 |
|---|---|---|
| `protocolVersion` | int | 必须为 1 |
| `clientId` | string | 客户端标识，写入 Host 日志 |
| `clientName` | string | 显示名 |
| `capabilities` | array<string> | 声明支持的能力，Host 不做逐项校验 |

### 3.3 HelloAck

| 字段 | 类型 | 说明 |
|---|---|---|
| `sessionId` | string（十进制 u64） | 后续所有帧的会话号 |
| `sessionToken` | string（base64） | 解出 32 字节密钥，用于 43101/43102/43103 的 HMAC |
| `protocolVersion` | int | 1 |
| `realtimePort` / `mediaPort` / `bulkPort` | int | 实际端口 |
| `heartbeatIntervalMs` | int | 250（客户端应在 100..2000 内取用） |
| `motionSendIntervalMs` | int | 50 |
| `motionLeaseMs` | int | 200 |
| `capabilities` | array<string> | Host 能力位 |
| `hostName` | string | 主机名 |

### 3.4 超时与断链

| 事件 | 阈值 | 结果 |
|---|---|---|
| 握手无 Hello | 5 s | Host 关连接 |
| 握手无 HelloAck | 3 s | 客户端重连 |
| 控制通道无任何入站帧 | 2 s（`2 × kSessionTimeoutMs`） | Host 关连接 |
| 控制发送缓冲积压 | 2 MiB（写帧时）/ 4 MiB（维护时） | Host 关连接 |
| `sequence` 回退或重复 | 立即 | Host 关连接 |
| 运动租约过期 | 200 ms | 车自动停，发 `robot.safetyStop` |
| 媒体分片未收齐 | 1.5 s | 丢弃该消息 |

## 4. 控制通道帧格式（TCP 43100）

### 4.1 头（50 字节，小端）

| 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0 | `magic` | u32 | `0x50413136`（字节序列 "PA16"） |
| 4 | `version` | u16 | 1 |
| 6 | `type` | u16 | 见 4.2 |
| 8 | `flags` | u16 | bit0 `ResponseToRequest`，bit1 `Urgent` |
| 10 | `sessionId` | u64 | 握手前为 0 |
| 18 | `sequence` | u64 | 每帧 +1，严格递增 |
| 26 | `requestId` | u64 | 请求与响应配对 |
| 34 | `timestampUs` | u64 | 微秒 |
| 42 | `payloadLen` | u32 | ≤ 1 MiB |
| 46 | `crc32` | u32 | 仅对 payload 的 CRC32（标准多项式 0xEDB88320，初值/结果取反） |
| 50 | `payload` | bytes | compact JSON |

### 4.2 类型

`1 Hello` / `2 HelloAck` / `3 Request` / `4 Response` / `5 Event` / `6 Ping` / `7 Pong` / `8 Error`

### 4.3 三种信封

```json
// Request
{"operation":"robot.enable","data":{"enabled":true}}

// Response
{"ok":true,"data":{...}}
{"ok":false,"errorCode":"invalid_argument","errorText":"..."}

// Event（event 名与数据平铺，没有 data 包一层）
{"event":"robot.clamp.position","axis":0,"index":0,"degrees":12.5}
```

`Error`（type=8）只用于协议级错误（握手未完成、会话号不符等），业务错误一律走 `Response{ok:false}`。

### 4.4 规则

- 握手完成前只接受 `Hello`，其它回 `Error{handshake_required}`。
- 握手完成后只接受 `Request` 与 `Ping`，其它回 `Error{unsupported_message}`。
- 未决请求上限 2048，单请求超时 5 s。
- 未知 `operation` 回 `unsupported_operation`。

### 6.4 超声参数

写入统一走 `ultrasound.parameters.apply`，读取统一走 `ultrasound.parameters.getMany`。
方法名即厂商 SDK 方法名，Host 按名透传并做参数个数校验。

**写入**

```json
{"operation":"ultrasound.parameters.apply","data":{"changes":[
  {"method":"setGain","args":[35.5,-1],"readbackMethod":"getGain","readbackArgs":[-1]},
  {"method":"setGateAStart","args":[2.0,-1],"readbackMethod":"getGateAStart","readbackArgs":[-1]}
]}}
```

- `changes` 1..512 条；每条 `method` 必须以 `set` 开头，`readbackMethod` 必须以 `get` 开头。
- 成功项进 `readbacks`（key 为 `method:base64(args JSON)`），失败项进 `errors`。
- 有任一项失败 → `ok=false`、`errorCode="parameter_apply_partial"`。
- 全部写完后 Host 执行 PRF 限幅（可能改写帧率并补读 `getFrameRate`），`limitMessage` 非空表示发生了限幅。

**读取**

```json
{"operation":"ultrasound.parameters.getMany","data":{"requests":[
  {"method":"getGain","args":[-1]},
  {"method":"getFrameRate","args":[]}
]}}
```

1..512 条；`getGain:[-1]` 中的 `-1` 表示“当前组”。

**参数表**

约定：`set*` 的 `args = [值, groupId]`，`get*` 的 `args = [groupId]`；`groupId = -1` 表示当前组。仅列特例。

| 组 | 方法（set / get 同名后缀） | 说明 |
|---|---|---|
| 扫描几何 | `BeamAngleLinear`、`BeamAngleMax`、`BeamAngleMin`、`BeamAngleStep`、`BeamAperture`、`BeamElementStep`、`BeamFirstElement`、`BeamLastElement`、`BeamMode`、`PointQuantity`、`RangeStart`、`RangeEnd` | 角度单位度，深度单位 mm |
| 接收 | `Gain`、`FilterHigh`、`FilterLow`、`ReceiverReject`、`RectifierMode`、`VideoFilterMHz`、`MaxAmplitude`、`ReverseEnable`、`DualCrystalEnable` | `VideoFilterMHz` 与 `RectifierMode` 为枚举 |
| 闸门 | `GateA/B/C/I` 各自的 `Enable`、`Start`、`End`、`Threshold`、`MeasureType`、`SynchronMode`；另有 `GateISyncSample` | 闸门 I 无 `MeasureType`/`GateIEnd` 之外的差异见签名 |
| 发射 | `PulseWidth`、`PaVoltage`、`UtVoltage`、`TransmissionChannel`、`ReceptionChannel`、`VoltagePolarity` | `PaVoltage`/`UtVoltage` 无 groupId：`args=[值]` |
| 探头 | `ProbeFrequency`、`ProbePrimaryElements`、`ProbePrimaryElementsPitch`、`ProbeSecondaryElements`、`ProbeSecondaryElementsPitch` | 改阵元会触发 PA 重建 |
| 楔块 | `WedgeEnable`、`WedgeAngle`、`WedgeHeight`、`WedgeLength`、`WedgeWidth`、`WedgeVelocity`、`WedgeX`、`WedgeZ`、`WedgeRoofAngle`、`WedgeGCp`、`WorkpieceVelocity` | |
| 聚焦 | `FocalPosition`、`FocusMode`、`TfmRecDelay`、`ScanType`、`ScannerDirection`（`args=[值]`）、`ScanMode`（`args=[值]`） | |
| TCG | `TcgEnable`；`TcgPointDepth`（`args=[index, depth, beamIndex, groupId]`）、`TcgPointDepthIndex`（`args=[index, depth, groupId]`）、`TcgPointGain`、`TcgPointGainIndex` | 点索引上限由 SDK 决定 |
| 其他 | `FrameRate`（`args=[值]`）、`Thickness`（`args=[值, groupId]`，groupId 必填）、`GroupsNo`、`BeamCounts` | 只读项用 `get*` |

参数个数不符时错误文本为 `参数个数错误：期望 N，收到 M`，据此可自查 args。

### 7.2 遥测（UDP 43101）

`type=3 Telemetry`，payload 为 JSON：

```json
{"kind":"driveTelemetry","hostTimeMs":123456789,
 "state":3,"stateKey":"enabled","reason":"",
 "commandFresh":true,"feedbackFresh":true,

 "appliedLinearMps":0.079,"appliedAngularRadps":0.0,

```

10 Hz 左右下发，latest-value 语义（丢一帧不影响）。仅当前 owner 能收到。

### 7.3 媒体（UDP 43102）

#### 头（58 字节，小端）

| 字段 | 类型 | 说明 |
|---|---|---|
| `magic` | u32 | `0x50413136` |
| `version` | u16 | 1 |
| `flags` | u8 | 固定 `0x01`（AuthPresent） |
| `kind` | u8 | 见 5.3 表 |
| `sessionId` | u64 | |
| `streamId` | u16 | 见流表 |
| `messageId` | u64 | 同流内自增 |
| `sequence` | u64 | 全通道自增 |
| `timestampUs` | u64 | |
| `totalBytes` | u32 | 整条消息字节数 |
| `fragmentIndex` | u32 | 从 0 起 |
| `fragmentCount` | u32 | |
| `payloadLen` | u32 | ≤ 1398 |

之后追加 16 字节 HMAC-SHA256（对“头+payload”整段计算，取前 16 字节）。单报 ≤ 1472 字节。

#### 流 ID

| streamId | kind | 载荷 |
|---|---|---|
| `0x0100 + groupId`（0..255） | 2 UltrasoundFrame | 数据帧 type 1 |
| `0x0201` | 4 LaserImage | 数据帧 type 3（JPEG，Host 已停发，仅旧版兼容） |
| `0x0202` | 5 LaserPointCloud | 数据帧 type 4 或 5 |
| `0x0203` | 9 ImuSample | 裸 9 个 double |
| `0x0204` | 10 LaserProfileObservation | 数据帧 type 6 |
| `0x0300 + slot`（0..1） | 6 UsbCameraImage | 数据帧 type 3（JPEG q=82） |
| `0x0401` | 7 CorrectionStatus | 已废弃，改走事件 `robot.autoCorrection.status` |

客户端必须实现：按 `streamId` 分桶组装 → 收齐 `fragmentCount` → 校验 `totalBytes` → 解 HMAC → 得整条 payload。收到更大 `messageId` 时直接丢弃旧桶（允许丢帧）。

#### 数据帧统一头

`magic "PAD1" = 0x50414431 (u32) | version 1 (u16) | type (u8)`

| type | 内容 | 压缩 |
|---|---|---|
| 1 | 超声单帧 `DecodedFrame`（A/B/C 扫 + 尾字段 + encoder[4] + 源波束） | `qCompress(...,4)` |
| 2 | 扫查批次 `GroupScanFrameBatch` | `qCompress(...,5)` |
| 3 | 图像：宽、高、格式、JPEG 字节 | 不压缩 |
| 4 | 点云：点数 (u32) + 每点 3×float | `qCompress(...,4)` |
| 5 | 量化点云：点数 + 原点 xyz(float) + scale(float) + 每点 3×qint16 | `qCompress(...,4)` |
| 6 | 焊道观测：点数 + 点 + frameNumber + receivedAtEpochMs + 52 个焊道字段 | 不压缩 |

`qCompress` 为 Qt 标准格式：首 4 字节是大端存储的原始长度，其后是 zlib 流。第三方非 Qt 实现需自行剥离该 4 字节后用 zlib 解压。

IMU 载荷无帧头，直接是 9 个 IEEE754 double（小端）：`roll, pitch, yaw, gyroX, gyroY, gyroZ, accX, accY, accZ`。

### 7.4 批量（TCP 43103）

头 28 字节：`magic u32 | version u16 | kind u16 | sessionId u64 | sequence u64 | payloadLen u32`，后 16 字节 HMAC。

- 连接后第一帧的 `sessionId` 用于定位密钥；HMAC 不对立即断链。
- `sequence` 严格递增，回退断链。
- 单帧 ≤ 32 MiB；Host 写缓冲高水位 8 MiB。

`kind`：`1 Heartbeat / 2 UltrasoundScanBatch / 3 RecordingPacket / 4 Configuration / 5 JsonEvent`。
当前只有 **2** 在用，payload 为数据帧 type 2（`qCompress(...,5)`）。客户端每 1 s 发一次 `kind=1` 心跳即可保活。

## 8. 配置数据格式

### 8.1 底盘 / 夹爪配置

`robot.connect`、`robot.settings.update`、`robot.clamp.settings.update`、`robot.clamp.connect`
的 `settings` 字段不是键值对，而是**整份 INI 的 Base64**：

```json
{"schema":13,"iniBase64":"W2RyaXZlXQpzZXR0aW5nc1NjaGVtYVZlcnNpb249MTM..."}
```

推荐工作流（避免手写全量键）：

1. 发 `robot.settings.get` 拿到当前 `settings.iniBase64`；
2. Base64 解码得到 INI 文本；
3. 修改目标键；
4. 重新 Base64，随 `robot.settings.update` 发回。

最小要求：INI 必须含 `[drive]` 组下的 `settingsSchemaVersion=13`（`DriveSettings::kCurrentSettingsSchemaVersion`），
且能通过 Host 的非串口校验。完整键表见 `src/robot/drive_settings.cpp` 的 `DriveSettings::save()`。

常用键（`[drive]` 组）：

| 键 | 含义 |

数组键的实际文本形如 `clampXMotors\1\mode`（QSettings IniFormat），建议不要手写。

## 11. 安全与并发

1. **单操作台独占**：Host 只允许一个控制会话。第二个连接能完成握手，但会收到 `host.busy`，250 ms 后断开，且其密钥不会注册到 43101/43102/43103，因此既不能控制也收不到数据。
2. **无鉴权**：控制通道只有 CRC32（防传输错误，不防人），会话密钥在 HelloAck 中明文下发。必须用网络隔离/防火墙限定来源 IP，只放行 43100–43103。
3. **急停不可替代**：软件急停（UDP `EmergencyStop` + TCP `robot.emergencyStop`）不能替代硬线急停，现场必须保留独立硬线回路。
4. **断链即停**：运动租约 200 ms，超时后 Host 主动停车并下发 `robot.safetyStop`。
5. **限幅在车上**：即使客户端下发超限值，Host 仍按自身限幅执行；不要依赖客户端限幅做安全。

## 12. 完整调用示例

### 12.1 设增益并确认生效

```text
1. TCP connect 192.168.1.20:43100
2. -> Hello      {protocolVersion:1, clientId:"OtherApp", clientName:"第三方", capabilities:["control.v1"]}
3. <- HelloAck   {sessionId:"7", sessionToken:"...", realtimePort:43101, motionLeaseMs:200, ...}
4. <- Event      {event:"host.ready", ...}
5. -> Request    requestId=2 {operation:"ultrasound.parameters.apply",
                              data:{changes:[{method:"setGain", args:[35.5,-1],
                                              readbackMethod:"getGain", readbackArgs:[-1]}]}}
6. <- Response   {ok:true, data:{readbacks:{"getGain:Wy0xXQ==":35.5}, errors:[], limitMessage:""}}
```

第 6 步的 `readbacks` 是**车端 SDK 回读值**。回读与期望不一致时该条会进 `errors`，不会进 `readbacks`。

### 12.2 使能并行驶

```text
1. -> Request  {operation:"robot.connect", data:{settings:{schema:13, iniBase64:"..."}}}
2. <- Response {ok:true, data:{queued:true, settings:{...}}}
3. -> Request  {operation:"robot.enable", data:{enabled:true}}
4. <- Event    {event:"robot.stateChanged", state:..., stateKey:"enabled", reason:""}
5. 用 sessionToken 解出 32 字节 key；UDP 向 192.168.1.20:43101 每 50 ms 发 MotionSetpoint：
   linearMilliMps=80, angularMilliRadps=0, ttlMs=200, 头+payload+16B HMAC
6. 收到 Telemetry 显示 appliedLinearMps 接近 0.08 即闭环生效
7. 停车：发一帧 linearMilliMps=0, angularMilliRadps=0；再发
   {operation:"robot.motion.stop"} 确认
```

注意：第 5 步一旦停发超过 200 ms，车会自动停。

### 12.3 接收超声图像

```text
1. media UDP socket bind 0.0.0.0:0
2. 每 500 ms 向 小车IP:43102 发 Heartbeat(kind=1, streamId=0, 带 HMAC)，让 Host 记住对端地址
3. 收包：校验 magic/version/flags/sessionId → 校验 16B HMAC
4. 按 streamId 分桶，收集 fragmentIndex 0..fragmentCount-1
5. 收齐后拼接 payload → 检查 PAD1 头 → type==1 → qUncompress → 按 DecodedFrame 布局解析
```

Host 在没收到过该会话心跳前会丢弃所有媒体（日志里表现为 `droppedNoPeer`），所以第 2 步必须先做。

## 13. 版本与兼容规则

1. `kProtocolVersion`、各帧头长度、`kMediaDatagramBytes`、`kProtocolVersion` 属于事实性常量，改动必须两端同时升级。
2. 客户端必须忽略未知 `event` 与未知 `MediaStreamKind`，不要因未知值断开。
3. 新增 `operation` 时只加分支，不改既有字段语义。
4. 服务端对未知 `operation` 返回 `unsupported_operation`，客户端应降级而非崩溃。

---

## 14. 已知实现约束（对接时按代码为准）

1. `robot.connectionChanged` 可能被发送两次（底层与 Host 各一次），客户端需幂等处理。
2. `robot.log` 是底盘日志，`robot.peripheral.log` 是外设日志，二者不合并。
3. `ultrasound.parameter.set`（单数）与 `ultrasound.parameters.apply/getMany/commit`（复数）并存，不要"归一化"。
4. `robot.autoCorrection.status`、`ultrasound.status` 既是 operation 名又是 event 名，语义不同。
5. `robot.clamp.positions` 只返回 Host 缓存，`settings.update` 会清空该缓存。
6. 超声前缀分派用 `startsWith`、内部用 `==`，形如 `ultrasound.parameters.commitXXX` 会被接收后再报"不支持"。
7. `robot.peripherals.snapshot` 与 `robot.sensors.snapshot` 返回同一份外设快照（不是底盘快照）。
8. `robot.camera.connect` 的 `source` 只要不是 `network` 就按 USB 处理。
9. 媒体流 `0x0201`（激光图像）与 `0x0401`（纠偏状态）在当前版本已不发送，客户端保留分支但不要求数据。
10. 底盘 `robot.connect` 排队返回 `{queued:true}` 不代表已连上，须等 `robot.connectionChanged{connected:true}`。

## A.1 小车运动（逐功能）

| 功能 | 端口 | 指令 | 报文 |
|---|---|---|---|

## A.7 数据回传（逐流）

| 数据 | 端口 | 识别方式 | 格式 | 解析 |
|---|---|---|---|---|
| 底盘状态/连接/日志 | TCP 43100 | `type=5` + `event` 名 | JSON | 见 7.1 |
| 夹爪位置/限位 | TCP 43100 | `event=robot.clamp.position` / `.limitReached` | JSON | 直接取值 |
| 超声预设失效 | TCP 43100 | `event=ultrasound.parameters.invalidated` | JSON | 需重读参数 |
| 轮速/轮位置/力矩/同步误差 | UDP 43101 | `type=3 Telemetry` | JSON | 见 7.2 |
| **超声 A/B/C/E 扫** | UDP 43102 | `streamId=0x0100+组号`, `kind=2` | 分片 + HMAC + `PAD1` type 1 + qCompress | 见 A.7.1 |
| **激光点云（预览）** | UDP 43102 | `streamId=0x0202`, `kind=5` | `PAD1` type 4/5 + qCompress | 见 A.7.2 |
| **激光焊道观测（完整）** | UDP 43102 | `streamId=0x0204`, `kind=10` | `PAD1` type 6，不压缩 | 点云 + 焊道 52 字段 |
| USB 相机画面 | UDP 43102 | `streamId=0x0300+slot`, `kind=6` | `PAD1` type 3 = JPEG 字节 | 直接解码 JPEG |
| IMU 姿态 | UDP 43102 | `streamId=0x0203`, `kind=9` | 9 个 double，无帧头 | 直接读 |
| 整包扫查批次 | TCP 43103 | `kind=2` | 28 B 头 + HMAC + `PAD1` type 2 + qCompress | 见 7.4 |

### A.7.1 超声帧（type 1）布局

```
u32 magic "PAD1" | u16 version=1 | u8 type=1
u32 beamCount
  重复 beamCount 次：u32 pointCount，然后 pointCount × qint16
u32 measurementCount
  重复 measurementCount 次：8 × double
    amplitudeA/B/C/I, positionA/B/C/I
u32 eScanImageBytes，然后该长度的 PNG
u8 frameError, u8 scannerIo, u8 multiFrame
u32 frameNumber, u8 encoderTriggerError, u8 encoderSyncError
4 × qint32 encoder
u64 timestamp
u32 sourceBeamCount, u32 selectedSourceBeam
```

外层还要：先做 UDP 分片重组 → 校验 16 B HMAC → `qUncompress`（剥离前 4 字节大端原始长度）→ 再按上面解析。

### A.7.2 点云

- type 4：`u32 pointCount` + 每点 3 × float（x/y/z）
- type 5：`u32 pointCount` + `float originX/Y/Z` + `float scale` + 每点 3 × qint16
  （还原：`x = originX + qx * scale`）

## A.8 按用途裁剪实现

| 你只做这些 | 需要实现的通道 |
|---|---|
| 只调超声参数（不显示图像） | TCP 43100 |
| 只控车（不设参数） | TCP 43100（连接/使能）+ UDP 43101 |
| 要超声图像 | + UDP 43102（含分片重组、HMAC、qUncompress） |
| 要激光点云/焊道 | + UDP 43102 |
| 要完整扫查批次 | + TCP 43103 |
| 要相机画面 | + UDP 43102 |

最小可用原则：**任何功能都至少需要 TCP 43100 完成握手**，因为没有 `sessionToken` 就拿不到 UDP 通道的密钥。
