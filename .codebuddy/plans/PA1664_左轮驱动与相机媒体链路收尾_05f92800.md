## 产品概述

小车（PA1664RobotHost，运行于 192.168.1.20）需恢复为可用状态：驱动轮可同步前进/后退、操作端能看到实时相机画面、主机双击即可稳定启动。

## 核心功能

- **驱动轮同步**：左右轮收到同一速度指令后按相同轮速运转；同步器能拿到两侧实测速度并给出补偿；消除"前进却像左转"的现象。
- **相机画面恢复**：操作端能持续收到两路相机与激光轮廓画面，延迟恢复正常，不再出现"完全停止"。
- **主机可靠启动**：双击 `app\PA1664RobotHost.exe` 或 `StartRobotHost.cmd` 均能启动，不再因残留 `robot_host.lock` 秒退。
- **可诊断性**：主机把 CAN 收发、媒体收发、驱动器状态等关键计数写入日志并转发到操作台，现场无需拷贝文件即可定位问题。

## 已确认的事实（作为边界）

- CAN 链路正常（左右各 11~17 帧/2s，`rx_other=0`、`bel=0`、`tx_failed=0`）。
- 左轮：速度字段恒 0、角度 `bc5e` 不变、扭矩约 -0.12A、`brake=released`、`err=0x0000`；右轮同帧格式正常工作。
- 0xA2 速度帧编码已修正并验证（`-5655 = -56.55 dps`）。
- 主机侧两路 RTSP 均连接成功（`dns SKIP 0ms`、`tcp 1ms`、`RTSP 200 OK 15ms`、1080p15）。
- 操作端实测接收仅 0.41 Mbps，画面冻结；主机在 Services 会话 0 时不出图，在 Console 会话时能出图（有卡顿）。
- 主机单实例锁在 PID 复用时会误判，导致双击秒退。

## 实施策略

### 1. 相机"完全停止"先定性，再修

`MediaServer::sendMessage` 在 `session.peer.valid == false` 时**静默 return**（`src/common/transport/media_channel.cpp:212-213`），而 peer 只能通过操作端已认证的心跳数据报学习。主机重启后若会话 ID/心跳不匹配，主机端会持续丢弃全部媒体且不写任何日志——与"主机侧相机一切正常、操作端只收到 0.41 Mbps"的现象完全吻合。

因此先补**双向计数与限频告警**（发送侧：no_peer / 超大 / 发送失败 / 成功帧数与字节；接收侧：收包数、组装完成数、组装超时丢弃数），2 秒窗口写一条，并复用已有 `diagnosticSink → robot.log → 操作台` 通道。计数一旦出来，成因（无 peer / 分片丢弃 / 带宽不足）即可直接判定，再决定是修心跳重协商还是降码率。

### 2. 左轮：逐级降级，不靠猜

- 现有：`0xA2` 编码修正 + 连接时 `0x88` 使能 + `0x8C` 松闸 + 左轮 `data[3]=0x00` + "1.2 s 不动则切 `0xF3`"（`wheel_motor_controller.cpp:808-827`，已确认位于 CAN 分支）。
- 补充：切换时把实际下发帧类型打进日志（`can_speed_frame data[0]=f3 ...`），使"是否真的发了 0xF3"可验证；若 `0xF3` 仍不动，再按 `0x88 → 0x8C → 0xA4（位置闭环绕过）` 的顺序做一次受限试探（位移不超过 1°，失败即恢复），并把每级结果写日志。
- 保持：不做与本次无关的重构；右轮路径不动。

### 3. 启动可靠性（已改，验证即可）

`src/backend/main.cpp` 已在 `QLockFile::tryLock` 失败时用 `tasklist /NH` 复核，确认无实例则删锁重试，`tasklist` 执行失败时保守不回退。保留该行为，不再远程启动进程。

## 性能与可靠性

- 媒体计数按 2 秒窗口聚合，避免日志风暴；`left_9c/right_9c` 原始帧已按窗口记录，不再逐帧打印。
- 位姿试探类动作（0xA4）限制角度与超时，失败立即 `0x81` 停车。
- CAN 轮询保持 15 ms 基础窗口 + 40 ms 扩展窗口，仅在丢应答侧触发，不增加正常路径开销。

## 关键代码结构

```cpp
// media_channel.h
struct MediaServerStats {
  quint64 messagesSent = 0;      // 成功完成 sendMessage 的消息数
  quint64 bytesSent = 0;         // 成功发出的分片总字节
  quint64 droppedNoPeer = 0;     // session 不存在或 peer.valid=false
  quint64 droppedOversize = 0;   // 超过 kMaxMediaMessageBytes / 分片上限
  quint64 sendFailures = 0;      // writeDatagram 失败
};
struct MediaClientStats {
  quint64 datagrams = 0;         // 收到的数据报
  quint64 messagesCompleted = 0; // 组装完成的消息
  quint64 assemblyTimeouts = 0;  // 超时丢弃的组装
};
```

## 执行与验证流程（固定）

1. 本机 `build\host.bat`（必要时 `build\build_both.bat`）；
2. `scp` 覆盖远端 `app\PA1664RobotHost.exe`，删除残留 `robot_host.lock`；
3. 由用户在小车桌面启动 `StartRobotHost.cmd`（不再由 AI 远程启动）；
4. AI 用 `ssh + powershell -EncodedCommand` 读 `app\logs\robot_console.log`，核对 `can_left_legacy_speed`、`left_9c` 角度变化、`MEDIA.TX` 计数与相机状态。
