## 产品概述

把现有"按协议分层 + 压缩表格"的附录，重写为一本**按功能查阅**的接口手册：读者想知道"做某件事该往哪个 IP、哪个端口、发什么指令、什么格式"，翻到对应条目即可，不需要再去别的章节拼凑字段。

## 核心功能

- **一条功能一个独立条目**，固定包含：方向、IP、端口、传输方式、指令名、可直接复制的完整报文、前置条件、返回/回传、失败表现。
- **完整覆盖七类内容**：

1. 小车运动 10 条（连接、使能、前进、后退、前进左转、原地右转、停车、急停、失能、断开）
2. 底盘参数逐个键（通信方式、电机 ID 与方向、车体几何、速度/加速度限幅、超时、同步 PI、IMU、激光、双路相机）
3. 夹爪与探头间距：每轴电机的全部配置项 + 点动、停、读位置、定位、连接、断开等指令
4. 超声参数按 7 组逐条（楔块、扫描几何、接收显示、闸门 A/B/C/I、发射、探头、聚焦/TCG/其他），每条给写入方法、参数顺序、回读方法
5. 超声功能（连设备、启停采集、状态、快照、预设增删改切、扫查精度、编码器标定、解码组配置）
6. 外设功能（IMU、激光、双路相机、自动纠偏）
7. 数据回传 9 类（状态事件、轮速遥测、超声帧、激光焊道、激光点云、相机、IMU、整包扫查批次）

- **报文可直接复制**：JSON 给完整对象而不是字段名列表；二进制数据给字段偏移、类型、长度和一段示例。
- **前置条件显式化**：例如"前进"必须标出需要先连接、再使能、并等待对应事件，避免读者发了报文却不动。
- **失败可判定**：每条注明会收到的错误码，或"没有任何反应"时该查什么。
- **按用途裁剪**：开头给出"只调参数 / 只控车 / 要图像 / 要点云"各自最少需要哪几条通道。

## 阅读效果

每个功能一屏内看完，标题即功能名；地址与端口是每条的第一行，不用跨章跳转；同类参数共用一次"统一入口"说明，条目内只保留该参数自己的方法名、参数顺序和示例片段，既完整又不重复。

### 三种条目模板（全书统一）

**A. 动作类（有请求-响应）**

```
### 前进
- 方向：上位机 → 小车
- IP：192.168.1.20（小车地址，下同）
- 端口：UDP 43101
- 传输：UDP，type=2 MotionSetpoint
- 指令：无 operation，直接发实时包
- 报文：linearMilliMps=+80、angularMilliRadps=0、ttlMs=200（字段偏移表 + 示例）
- 前置：握手 → robot.connect → robot.enable → 收到 stateKey="enabled"
- 回传：UDP Telemetry 中 appliedLinearMps 接近 0.08
- 失败表现：停了 200 ms 自动停；未使能则 applied 恒为 0
```

**B. 参数类（配置项）**

```
### 楔块角度
- 端口：TCP 43100
- 写入：setWedgeAngle，args=[18.5, -1]
- 回读：getWedgeAngle，args=[-1]
- 报文：{"changes":[{"method":"setWedgeAngle","args":[18.5,-1],
        "readbackMethod":"getWedgeAngle","readbackArgs":[-1]}]}
- 说明：单位度；groupId=-1 为当前组；回读值在 readbacks 中
```

**C. 回传类（数据流）**

```
### 激光焊道观测
- 端口：UDP 43102（先发 kind=1 心跳）
- 识别：streamId=0x0204，kind=10
- 帧结构：58 B 头 → 16 B HMAC → PAD1 type=6
- 载荷布局：点数字段 + 每点 3×float + 帧号 + 时间戳 + 焊道字段数 + 各字段
- 解析步骤：1 校验头 2 校验 HMAC 3 分片重组 4 读 type 5 逐字段取值
- 失败表现：HMAC 不符丢弃；未发心跳则收不到任何包
```

### 事实基准与核验方式

- 端口、帧头、流 ID、常量：以 `src/common/protocol/protocol_types.h` 与各 codec 为准。
- operation 与 data 字段：以 `src/backend/*_host_service.cpp` 的 dispatch 分支为准。
- 参数个数与顺序：以 `src/backend/ultrasound_parameter_rpc.cpp` 的 `checkArgs` 与 `getterNames/defaultArguments` 为准。
- 底盘键名：以 `src/robot/drive_settings.cpp` 的 `DriveSettings::save()` 为准（不手工臆造）。
- 完成前做一次反向比对：从代码抽取 operation 字符串清单，与手册条目逐条对齐，缺失或多写的列成差异清单修掉。

### 实现要点

- 参数条目不重复写"如何下发"的完整流程，只在每组开头写一次统一入口，条目内保留方法名、args、示例片段。
- 二进制布局用"偏移/类型/长度/含义"四列表，避免纯文字描述导致歧义。
- 所有示例数值标注单位与取值范围，避免第三方按错单位下发。
- 保持中文，出现代码片段一律 C++/Qt 风格。
