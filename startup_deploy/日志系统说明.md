## 📝 日志内容说明

### 日志格式
\\\
时间戳 #序号 [线程ID] [级别] [模块] event=事件 详细信息
\\\

**示例:**
\\\
2026-09-23 10:18:23.024 #00000001 [Tda8] [INFO] [SYSTEM] event=application_start result=OK
\\\

### 日志级别
- **[INFO]** - 正常操作信息（启动、连接成功、状态变更等）
- **[WARN]** - 警告信息（配置缺失、非关键失败等）
- **[ERROR]** - 错误信息（连接失败、设备故障等）
- **[DEBUG]** - 调试信息（详细的内部状态）

## 🔍 关键日志模块

### 1. SYSTEM（系统模块）
记录程序启动、关闭、线程管理
\\\
event=application_start      # 程序启动
event=application_exit       # 程序退出
event=thread_start           # 线程启动
event=thread_stop            # 线程停止
\\\

### 2. DRIVE.CONTROL（底盘控制）
记录电机连接、驱动状态、运动控制
\\\
event=connect_start          # 开始连接电机
event=state_changed          # 底盘状态变化
event=motion_command         # 运动指令
event=emergency_stop         # 急停
\\\

### 3. IMU.COMM（惯性测量单元）
记录IMU连接、姿态数据
\\\
event=connect_start          # 开始连接IMU
event=connect_failed         # 连接失败
event=data_received          # 接收姿态数据
\\\

### 4. CAMERA（相机模块）
记录相机连接、图像采集
\\\
event=connect_start          # 开始连接相机
event=frame_captured         # 图像采集
event=connection_lost        # 连接丢失
\\\

### 5. CORRECTION.CONTROL（纠偏控制）
记录自动纠偏过程 - **重要故障排查**
\\\
event=correction_start       # 开始纠偏
event=seam_detected          # 检测到焊缝
event=offset_calculated      # 计算偏移量
event=correction_applied     # 应用纠偏
event=correction_failed      # 纠偏失败
\\\

### 6. UI.OPERATION（用户操作）
记录用户界面操作
\\\
event=connect_all_request    # 连接所有设备
event=button_clicked         # 按钮点击
event=parameter_changed      # 参数修改
\\\

## 🛠️ 故障排查场景

### 场景1: 自动纠偏失败
**查看日志:**
\\\powershell
# 搜索纠偏相关日志
Select-String -Path "logs\*.log","RobotControl\logs\*.log" -Pattern "CORRECTION" | Select-Object -Last 50
\\\

**关键事件:**
- \vent=correction_start\ - 纠偏是否启动？
- \vent=seam_detected\ - 是否检测到焊缝？
- \vent=offset_calculated\ - 偏移量是多少？
- \vent=correction_failed\ - 失败原因？

### 场景2: 设备连接失败
**查看日志:**
\\\powershell
Select-String -Path "RobotControl\logs\robot_console.log" -Pattern "connect_failed|ERROR" | Select-Object -Last 20
\\\

**检查项:**
- 端口号是否正确（COM6, COM7等）
- 错误信息（系统找不到指定的文件 = 端口不存在）
- 设备是否上电

### 场景3: 通信中断
**查看日志:**
\\\powershell
Select-String -Path "logs\*.log" -Pattern "connection_lost|disconnect|timeout"
\\\

### 场景4: 程序崩溃
**查看日志:**
\\\powershell
# 查看最后的日志条目
Get-Content "RobotControl\logs\robot_console.log" -Tail 100
\\\

查找 \vent=application_exit\ 前的错误信息

## 📊 日志管理

### 自动清理策略
程序内置日志清理功能：
- SDK日志（log_YYYYMMDD_HHMMSS.txt）会自动清理旧文件
- 主日志需要手动管理

### 手动清理建议
\\\powershell
# 删除30天前的日志
Get-ChildItem -Path "logs","Mv3dLpLog","RobotControl\logs" -Recurse -File | 
    Where-Object { \.LastWriteTime -lt (Get-Date).AddDays(-30) } | 
    Remove-Item -Force
\\\

### 日志归档
\\\powershell
# 压缩并归档日志
\ = Get-Date -Format "yyyyMMdd"
Compress-Archive -Path "logs","Mv3dLpLog","RobotControl\logs" -DestinationPath "logs_archive_\.zip"
\\\

## 🔧 日志级别调整

日志级别在源码中配置，默认为 INFO 级别。

如需更详细的调试日志，需要在源码中修改并重新编译：
\\\cpp
// src/backend/main.cpp 或 src/main.cpp
qSetMessagePattern("[%{time yyyy-MM-dd hh:mm:ss.zzz}] [%{type}] %{message}");
\\\

## ⚙️ 程序启动时的日志行为

### Robot Host 启动
1. 创建 \logs\ 目录（如果不存在）
2. 打开 \logs\robot_console.log\（追加模式）
3. 记录 \vent=application_start\
4. 启动各模块线程
5. 尝试连接保存的设备配置

### Operator Workbench 启动
1. 创建 \logs\ 目录
2. 清理旧的 SDK 日志文件
3. 打开日志文件
4. 记录启动信息
5. 等待用户连接机器人
